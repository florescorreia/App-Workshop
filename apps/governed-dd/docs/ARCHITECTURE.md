# Actual local architecture

Control plane has4 services: nginx gateway, FastAPI portal, Keycloak26.4.7 and dedicated PostgreSQL. Portal/identity use separate databases/roles. Only gateway publishes loopback8081. Identity/admin credentials remain app-owned.

A base tenant has5 services: dedicated ParadeDB PostgreSQL, governance FastAPI/FastMCP, Memgraph, Explorer and Paperclip. Supported Codex CLI SSH execution adds analyst runtime, separate reviewer runtime and provider-egress proxy (8 total); optional owner-only Lab adds one (9). A currently has execution/Lab; B has base services and provisioned native users. Full second execution is refused by configured memory reservations on the15.33 GiB engine.

Each tenant has isolated backend, ingress and execution networks. Runtime sees tenant governance and provider proxy, no database/graph/admin volumes or other tenant routes. Paperclip is on backend/ingress/runtime but generated analysis executes remotely as UID1000 in separate SSH containers. Pinned upstream environment allowlist patch removes inherited server variables from remote environment serialization. Model and agent keys exist only in scoped runtime files/environment. Reviewer has its own key, home and workspace; both roles share a tenant execution file lock. Nonprivileged bubblewrap failed and is not claimed.

Portal joins individual tenant ingress networks and control. Native Paperclip/Lab use opaque component origins and single-use30-second membership tickets. Whole-path HTTP and websocket authorization uses a current control session/membership. Native Paperclip authentication is separately required. Lab is owner-only because community Memgraph privileges cannot establish read-only roles.

Canonical revisions/audit/outbox commit together in PostgreSQL. Source/artifact bytes are immutable SHA-256-addressed files. Serving DD role appends canonical history and cannot UPDATE/DELETE records/audit or create schema after explicit hardening. Extraction jobs persist progress; graph projection replays canonical version keys. Approved ontology YAML is canonical in PostgreSQL and exported as versioned commits to a dedicated tenant Git volume. Analytical Git and Codex workspaces are external named volumes.

Retrieval uses actual pg_search BM25 and pgvector. Dense embedding configuration validates dimensions/model identity and requires real provider acceptance; currently absent. Search combines rank lists through reciprocal rank fusion and bounded graph expansion. Controlled public fetch validates DNS/redirects/IPs and verifies TLS; public search requires explicit authorization and configured provider.

Persistent control volumes: database, frontend build, private identity credentials. Persistent tenant volumes: postgres, graph, artifacts, paperclip, analytical git, analyst home, reviewer git/home, shared run gate, ontology and optional Lab. Encrypted offline backups capture volumes and private configuration; restore uses fresh prefixed volumes. No runtime repository/client artifact enters platform Git.

PRD acceptance remains incomplete where recorded in VERIFICATION.md; this diagram does not prove exhaustive host isolation or an accepted production deployment.
