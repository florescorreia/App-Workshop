# IdeaFlow and VAVE user guide

Open [IdeaFlow](https://vps-8104e6c8.vps.ovh.us:8443) with your existing account. The landing page is **VAVE programs**. **My VAVE work** brings together owned ideas, assigned implementation actions, screening and gate reviews. **VAVE walkthrough** explains program work; **Earlier IdeaFlow** retains the original screens. Passwords remain unchanged.

The user-authorized evaluation program adapts IF-00205 to **Simplify the actuator mounting bracket** (M2, functional validation still required) and IF-00206 to **Introduce returnable packaging for actuator deliveries** (Draft/M0, economics unknown). Titles and concepts fit VAVE; History → Prior IdeaFlow evidence retains their former records and financial evidence. The €36,000 bracket opportunity and €50,000 target are illustrative estimates. Approved/implemented/verified benefits remain zero until the respective evidence and decisions are recorded.

1. Establish a program with your actual client, objective, sponsor, product scope, currency, period and savings rules. Select participating accounts and the responsible Manager, Functional, Finance and Authority reviewers. Add targets and required evidence. Create accounts through Admin Settings first if needed.
2. Capture an idea with title, proposed change and scope; save a draft and submit through Gates. A Manager assigns one owner, next action and date, records an M1 review and explicitly advances it. Unknown economics remain blank.
3. Develop case → Economics: add a distinct benefit application for each part/plant/financial scope. Enter comparable unit costs, dated baseline evidence, annual quantity, monthly eligible quantities/adoption, implementation timing, recurring offsets, sharing and one-time cash spend. Keep value types separate. Give overlapping alternatives the same overlap reference and select one.
4. Develop case → Feasibility: record required function/constraints, mandatory acceptance evidence and risks/mitigations. Finance reviews M2; Functional and Finance review M3. From Gates, request review, record each assigned review and have a Manager/Authority advance the gate. Missing requirements prevent passage.
5. Develop case → Delivery: add proportionate implementation actions/milestones, owners, dates, predecessors and evidence. Authority and threshold-required Finance review M4. Record each application's release and production cut-in. M5 requires all selected applications in production and all required actions complete; partial rollout remains visible.
6. Economics → Actual evidence: choose an application and fully elapsed month in its defined monthly observation schedule and program horizon, record eligible quantity and observed cost, recurring costs/sharing, cash spend, evidence and variance/external effects. A different Finance reviewer enters a reason and verifies the saved period. Idea owner, application owner and recorder self-verification are blocked. Negative benefits are retained. Corrections clear prior verification and require a new independent review. M6 requires verification for all eligible elapsed application periods.
7. Material scope/economics/timing changes flag approvals and retain earlier snapshots in History. Reapprove the current affected gate explicitly. Hold needs a responsible owner and review date; terminal dispositions require lessons and final disposition. Reopen or return with a reason to continue work. Superseded records link to the survivor and keep their discussions/history.
8. Use the register's filters, My owned ideas/actions and saved personal views. Leadership/finance reports state metric, period, scope, currency, conversion basis and freshness and expose supporting applications/exclusions. Meeting review highlights assignment gaps, overdue work, blockers and stale ideas. Print a review pack or export the filtered register. Import existing CSV lists by mapping capture columns, validating, reviewing errors/duplicates and confirming the exact preview.

Upload supporting files under Evidence and discussion (maximum 5 MiB each). Files and checksum metadata survive container rebuilds and are included in database backups. Mark a file/discussion and its idea explicitly shared before an External member can see them. External participants cannot see commercially sensitive economics, private program records, another program's data or the original shared workspace.

Search the register by title, part, supplier or scope; filter product, category, plant, owner and maturity, then sort/group or save a personal view. Leadership and finance → Reporting from/through, Product and Plant controls select the report scope. A filtered report uses only a matching target metric/period/scope; otherwise its target is Unknown. Unquantified applications remain visible as Unknown rather than implying zero opportunity. Selecting a metric opens supporting applications and exclusions. Leadership Viewer has read access to these reports without decision rights.

On VAVE programs, routine approaching-deadline notices can be switched off. Assignment, review, returned/material-change and overdue governance notices remain visible. Meeting review shows Manager escalation issues; open the linked record to update actions or record a decision. No email service is required.

Annual run rate, in-year recurring benefit and net cash are different metrics. A $10 → $9 part on 100,000 annual units gives $100,000 gross run rate. With 40,000 eligible in-year units, gross is $40,000. A $0.10 recurring offset yields $36,000 in-year net recurring benefit; $20,000 cash spend leaves $16,000 net cash. Implementation alone creates no verified saving. Parent targets include allocated children; only explicitly additional child targets increase the program target.

Production and local verification are independent databases. Never import a historical local backup into production as a code update. See [VPS operations](VPS_IDEAFLOW.md), [redeployment](REDEPLOY.md) and [verification evidence](VERIFICATION.md).
